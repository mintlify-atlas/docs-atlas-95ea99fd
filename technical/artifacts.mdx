Better-NiDA commits all generated artifacts to the repository. This page documents every artifact, what it contains, and how it is produced.

<Warning>
  Hand edits to any generated artifact are overwritten by the next pipeline run. Change the generator script instead — see the [Windows scripts reference](/technical/scripts-windows) for which script produces each file.
</Warning>

---

## The authoritative spec

### nida_layout.json

The machine-readable NiDA specification: 49 keys, all modifier states, 5 ligatures, and official Unicode character names sourced directly from the UCD. Generated by `export_nida_spec.ps1`.

This is the **single source of truth** for the macOS and Linux layouts. Both `build_platform_layouts.ps1` and `build_installers.ps1` read from this file. Any change to what a user types must flow through a change here.

---

## Driver decode artifacts

Produced by loading `kbd*.dll` in-process, calling its `KbdLayerDescriptor()` export, and walking the returned descriptor tables.

| File | Contents | Generated by |
| :-- | :-- | :-- |
| `tables_kbdkni.json` / `.csv` | Every table decoded directly from `kbdkni.dll` | `dump_kbd_tables.ps1 -Dll kbdkni.dll` |
| `tables_kbdkhmr.json` / `.csv` | Same for the legacy Khmer layout | `dump_kbd_tables.ps1 -Dll kbdkhmr.dll` |
| `tables_kbdus.json` / `.csv` | Same for the US layout (structural control) | `dump_kbd_tables.ps1 -Dll kbdus.dll` |

The `.json` file for each DLL contains the full decoded descriptor: modifier numbering, all character sub-tables, ligature records, and secondary tables. The `.csv` is the main character map only — one row per key/state — and is the file consumed by `verify_tables.ps1`.

## Behavioural probe artifacts

Produced by calling `ToUnicodeEx` for every scan code in every modifier state. Completely independent of the DLL's binary format; serves as the oracle that validates the structural decode.

| File | Contents | Generated by |
| :-- | :-- | :-- |
| `kni_layout.csv` | Behavioural probe of NiDA (`ToUnicodeEx`) | `dump_layout.ps1` |
| `khmr_layout.csv` | Behavioural probe of legacy Khmer | `dump_layout.ps1` |
| `kni_control.csv` | Probe of NiDA with `VK_CONTROL` held | `dump_layout_control.ps1` |
| `us_control.csv` | Same probe for US (tests table 2's role claim) | `dump_layout_control.ps1` |

**Verification result:** 144 of 144 comparisons between the structural decode and the behavioural probe agree, zero mismatches. The Control probe adds 4 of 4. `verify_tables.ps1` and `verify_control.ps1` reproduce these checks and exit non-zero on any disagreement.

## Platform layout files

Generated from `nida_layout.json` by `build_platform_layouts.ps1`. Two variants are always produced together from the same generator, so they cannot drift apart.

| File | Contents | Generated by |
| :-- | :-- | :-- |
| `macos/Khmer NiDA.keylayout` | Apple XML keylayout for Khmer NiDA | `build_platform_layouts.ps1` |
| `macos/Khmer NiDA Legacy.keylayout` | Apple XML keylayout for the legacy variant | `build_platform_layouts.ps1` |
| `linux/nida` | XKB symbols file, `FOUR_LEVEL` | `build_platform_layouts.ps1` |
| `linux/nida_legacy` | XKB symbols file, `EIGHT_LEVEL` | `build_platform_layouts.ps1` |

**Ligature handling:** macOS keylayouts can emit multiple code points per keystroke, so all five NiDA ligatures are reproduced faithfully. XKB maps one keysym per level, so the five ligature keys fall back to their first code point on Linux; each affected line is marked `LIGATURE truncated`. For full ligature support on Linux, see `linux/m17n/`.

<Warning>
  The platform layout files (`macos/*.keylayout`, `linux/nida*`) have been validated structurally on Windows but have **not** been loaded on real macOS or Linux hardware. If you have a Mac or Linux box, installing and testing the layout is the most useful contribution you can make right now. Use the *Testing Report* issue template on GitHub.
</Warning>

## Determinism guarantee

All generated artifacts are byte-identical between runs on the same Windows build.

- Any diff after a clean regeneration means a real change in the source or toolchain.
- Use `verify_all.ps1 -SkipRegenerate` in CI to check committed artifacts without regenerating them.

```powershell
.\scripts\verify_all.ps1 -SkipRegenerate
```
