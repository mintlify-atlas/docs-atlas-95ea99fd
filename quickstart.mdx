This quickstart gets you typing Khmer with Better-NiDA as fast as possible.
You do not need to run any build tools or regenerate any files — the verified
layout files are committed to the repository and ready to install. Pick your
platform below, follow the steps, and verify a handful of keys to confirm
everything is working.

---

## Install

<Tabs>
  <Tab title="macOS">
    <Steps>
      <Step title="Get the layout files">
        Clone the repository or download the release archive. The layout files
        are in the `macos/` directory — no build step is needed.

        ```sh
        git clone https://github.com/airiharuki/Better-NiDA.git
        cd Better-NiDA
        ```
      </Step>

      <Step title="Install the layouts">
        You have two options. Use whichever suits your setup:

        **Option A — Shell script (recommended, no password needed)**

        Copies both `.keylayout` bundles into `~/Library/Keyboard Layouts`,
        affecting only your own account:

        ```sh
        cd macos && ./install.sh
        ```

        **Option B — Double-clickable `.pkg` (system-wide, asks for password)**

        Build the installer first, then double-click the resulting file and
        follow the prompts:

        ```sh
        cd macos && ./make-pkg.sh
        # Opens dist/Khmer-NiDA-Layouts-1.0.0.pkg — double-click to install
        ```
      </Step>

      <Step title="Enable the layout in System Settings">
        Open **System Settings → Keyboard → Text Input → Edit...**, click
        **`+`**, then select **Others...** from the left-hand list. You will see
        **Khmer NiDA** and **Khmer NiDA Legacy** — add whichever you need.

        If neither appears in the list straight away, **log out and back in**.
        macOS caches its keyboard layout list, and the installer nudges but does
        not always immediately refresh it.
      </Step>

      <Step title="Verify a few keys">
        Switch to the Khmer NiDA input source and open a Unicode-aware editor
        such as TextEdit or VS Code. Check these keys:

        | Key | Expected output |
        | :-- | :-- |
        | `J` | `U+17D2` coeng ្ |
        | `Space` | `U+200B` zero-width space (invisible) |
        | `Shift+Space` | `U+0020` real visible space |
        | `Shift+A` | `U+17B6 U+17C6` ាំ (single key press, two code points) |
        | `Shift+V` | `U+17C1 U+17C7` េះ |
        | `Shift+;` | `U+17C4 U+17C7` ោះ |
        | `,` | `U+17BB U+17C6` ុំ |
        | `Shift+,` | `U+17BB U+17C7` ុះ |

        The five ligature keys (`Shift+A`, `Shift+V`, `Shift+;`, `,`,
        `Shift+,`) each emit two code points from a single key press on macOS —
        all five should work. If a character appears as a missing-glyph box, the
        app may not support Khmer shaping; try a different editor.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Linux">
    <Steps>
      <Step title="Get the layout files">
        Clone the repository or download the release archive. The layout files
        are in the `linux/` directory.

        ```sh
        git clone https://github.com/airiharuki/Better-NiDA.git
        cd Better-NiDA
        ```
      </Step>

      <Step title="Install the layouts">
        Run the installer from the `linux/` directory. No root is required —
        everything is installed per-user under `~/.xkb`.

        ```sh
        cd linux && ./install.sh              # NiDA layout (default)
        # or:
        ./install.sh nida_legacy              # Legacy layout instead
        ```

        Running the installer twice is safe. To remove the layouts entirely:

        ```sh
        ./install.sh --remove
        ```
      </Step>

      <Step title="Enable the layout in your desktop environment">
        After installing, add the layout through your desktop's keyboard
        settings. Look under **Keyboard → Layouts → Add → Others** for
        **"Khmer NiDA"** or **"Khmer NiDA Legacy"**:

        | Desktop | Path |
        | :-- | :-- |
        | GNOME | Settings → Keyboard → Input Sources → `+` |
        | KDE Plasma | System Settings → Keyboard → Layouts → Add |
        | Xfce | Keyboard → Layout → `+` Add |
        | Cinnamon | Keyboard → Layouts → Add |
      </Step>

      <Step title="Verify the active layout">
        Run the bundled verification script to confirm the installed layout is
        correct:

        ```sh
        ./verify.sh           # inspect whichever layout is currently active
        ./verify.sh nida      # inspect nida without activating it
        ```

        Then confirm these keys manually in a text editor:

        | Key | Expected output |
        | :-- | :-- |
        | `J` | `U+17D2` coeng ្ |
        | `Space` | `U+200B` zero-width space (invisible) |
        | `Shift+Space` | `U+0020` real visible space |
        | `1` | `U+17E1` Khmer digit one |
        | `` ` `` | `U+00AB` « (left angle quotation mark) |
      </Step>
    </Steps>

    <Note>
      **Ligature limitation on Linux.** XKB can only emit one character per key
      per level, so the five ligature keys (`Shift+A`, `Shift+V`, `Shift+;`,
      `,`, `Shift+,`) each produce only their **first** code point rather than
      the full two-character sequence. The affected entries are marked
      `LIGATURE truncated` in the installed file — check with
      `grep LIGATURE ~/.xkb/symbols/nida`. If you need the full ligature
      sequences, install the optional **m17n input method** from `linux/m17n/`
      instead.
    </Note>
  </Tab>
</Tabs>

## NiDA vs. Legacy: which should I use?

| Feature | Khmer NiDA | Khmer NiDA Legacy |
| :-- | :-- | :-- |
| Windows driver | `kbdkni.dll` (KLID `00010453`) | `kbdkhmr.dll` (KLID `00000453`) |
| Coeng ្ (`U+17D2`) | `J` | `Space` |
| Zero-width space (`U+200B`) | `Space` | `/` |
| Modifier levels | 4 (Normal / Shift / Control / AltGr) | 5 (+ Shift+AltGr) |
| Shift+AltGr level | Not available | Khmer symbol block `U+19E0–U+19FF` |
| Recommendation | Current national standard | Needed for `U+19E0–U+19FF` symbols or legacy muscle memory |

Choose **Khmer NiDA** if you are following the current NIDA national standard.
Choose **Khmer NiDA Legacy** if you need the Shift+AltGr symbol block, or if
you are migrating from an older setup where the spacebar typed the coeng
subscript.

## What to do if something looks wrong

Both platform layouts were structurally validated on Windows but have not yet
been confirmed on real macOS or Linux hardware. If a key produces the wrong
character, does not appear in your desktop's input-source list, or behaves
unexpectedly in any way:

1. Run the platform checklist (`macos/README.md` or `./verify.sh` on Linux)
2. Note the key, modifier, and what you got vs. what was expected
3. Open a **Testing Report** issue on GitHub

Even a simple "it works" report is valuable — it establishes a confirmed-working
baseline on hardware that has not been tested yet.
